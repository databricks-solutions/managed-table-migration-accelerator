Freeze bracket — …e2e_real_stream

Everything that could write to or rewrite these tables is paused so convert copies a clean, unchanging snapshot.

What freezing turns off — and why

Convert copies the latest snapshot of each table. Anything that writes or rewrites files mid-copy can corrupt that snapshot (a VACUUM or OPTIMIZE can even fail the conversion). So the freeze pauses each source of change, in this order:

  • Compaction / OPTIMIZE jobs — scheduled jobs that rewrite files. Paused via PAUSE_JOB.
  • Predictive Optimization — Databricks auto-optimize for the schema. Turned off via DISABLE_PO (only re-enabled later if it was ON before).
  • DLT pipelines writing to these tables. Stopped via STOP_PIPELINE; restarted from checkpoint, never full-refresh.
  • Structured Streaming writer jobs. Stopped via STOP_STREAM_JOB; restarted from checkpoint.
