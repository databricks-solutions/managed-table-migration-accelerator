What gets in the way

  1. 1The button is last, after about 10 open sections. The spec says three decision facts and collapsed detail; the freeze card already does this, the general card never did.
  2. 2Two different things are called "By schema". One navigates to Waves, the other expands in place.
  3. 3Two misleading numbers. "337 to freeze" counts actions, not tables, beside table counts. "11 held back" is dropped because the subline type-checks for a number and AppKit sends a string (estateSubline.pure.ts:51).
  4. 4Tiles have no "out of what". Percentages and a count side by side, none with a total.
  5. 5Focus mode is hard to find. The picker is off screen and the schema rows don't look clickable.

Same data, same order, same buttons. Only what is open by default changes. Layer 1 answers "what next, is it safe, what does it touch". Layer 2 is one click. Layer 3 (CLI) stays where it is. Try the disclosures; they reveal in 200 ms with opacity only under reduced motion.

What changed, and what didn't

  1. 1Decide layer first. Chips, title, the lifecycle spine, one verdict line, four facts (downtime is its own), then the button. Everything else moves into three collapsed sections. Nothing is deleted. The engine's "Set action=advance" text is labelled Technical, inside Details.
  2. 2One "By schema". The expanding list keeps the name; the link to the Waves page becomes "All waves →".
  3. 3Honest counts. "11 held back" is shown (the string-vs-number fix) with a Review link, and the journey reads "337 items to pause".
  4. 4Every tile says "of what". The labels keep the words the e2e checks read ("Migrated", "Validated", "Remaining", "Schemas blocked").
  5. 5Focus mode is beside the list. Each row has a visible "Open →", and the held-back tables appear as a footer row instead of vanishing.
